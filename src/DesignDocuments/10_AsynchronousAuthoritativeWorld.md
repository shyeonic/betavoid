# 비동기 권위 월드 구현 원칙

작성 기준: 2026-08-02

이 문서는 beta-void를 실시간 전투 시뮬레이션이 아닌 스케줄러 기반 방치형 MMORPG로 이전할 때 지켜야 하는 권위 경계와 구현 순서를 명시한다. 기존 싱글플레이 규칙의 결과와 시드 구조는 유지하되, 브라우저 저장소는 캐시와 화면 투영에만 사용한다.

## 1. 게임의 서버 모델

beta-void는 다음 두 계층으로 나눈다.

1. 권위 월드
   - 항해 계약, 소속, 자산 이전, 채굴 결산, 생산 결산, 전투 작전 결과를 확정한다.
   - Worker와 D1의 단일 명령 경로가 논리적인 단일 서버다.
   - 서버 시각과 액션 시작 시 고정한 규칙을 사용한다.
2. 로컬 경험
   - 자유 조작, 카메라, 애니메이션, 이펙트와 예측 진행률을 담당한다.
   - 서버 결과를 변경하거나 경제 상태를 확정할 수 없다.

Presence와 알림은 세 번째 보조 계층이다. 연결 상태, WebSocket, alarm 성공 여부는 게임 결과의 근거가 아니다.

## 2. 불변 규칙

- GET은 초기 계정·함선 생성 이외의 게임 상태와 revision을 변경하지 않는다.
- 시간 경과만으로 함선 revision을 올리지 않는다.
- 현재 상태는 `저장된 기준점 + serverNow`에서 파생한다.
- 파생 상태의 영속 결산은 다음 도메인 명령과 같은 권위 경계에서 수행한다.
- 명령은 `client_action_id`, 발급 시각, 만료 시각을 가진다.
- 만료된 명령은 실행하지 않으며 자동 재전송하지 않는다.
- 응답 유실 확인은 명령 receipt 조회로만 수행한다. 원본 명령을 다시 만들지 않는다.
- 하나의 경제 명령은 관련 월드 오브젝트와 자산을 같은 D1 원자 단위로 변경한다.
- 스케줄러와 Durable Object는 알림·압축·인덱스 보조에만 사용할 수 있다.
- 로그아웃과 소켓 종료는 함선과 자산을 월드에서 제거하지 않는다.

## 3. 시간 기반 수명주기

### 3.1 베타보이드

저장 레코드는 마지막 권위 기준점이다. 조회 시 서버는 다음 경계를 반복 재생해 현재 세대를 계산한다.

- 활성 상태: `active_reset_at`
- 격파 상태: `next_regeneration_checkpoint`
- 다음 상태의 난수: `worldSeed + betaVoidId + boundaryKind + boundaryAt`

경계 재생은 DB를 수정하지 않는다. 실제 격파 명령만 상태를 기록한다. 격파 명령은 해당 함선이 같은 베타보이드와 세대의 활성 Beta Space 세션에 있는지 검증한다.

함선의 귀환 기준점은 Beta Space 진입 시 세션에 고정한다. 이후 베타보이드가 이동하거나 재생성되어도 귀환 좌표는 바뀌지 않는다.

### 3.2 자원 노드

자원 수명주기는 로그인 시 실행하는 멱등 `WORLD_RECONCILE` 명령으로 지연 결산한다.

- 경계는 `resourceManager.next_check`다.
- 누락된 경계는 예정되었던 경계 시각 순서로 재생한다.
- 난수 시드는 `worldSeed + resource-cycle + boundaryAt`이다.
- 만료·고갈 노드를 제거하고 정의의 총량, 회차 생성 상한, 노드 용량, 섹터 가중치를 적용한다.
- 같은 경계를 다시 요청하면 `next_check`가 이미 전진했으므로 쓰기가 발생하지 않는다.

브라우저 접속 시각을 시드에 포함하지 않는다. 브라우저가 명령을 촉발할 수는 있지만 결과와 유효성은 서버만 결정한다.

## 4. 항해와 필드 표시

자동항해는 시작점, 목표점, `flightAt`, `arriveAt`, 고정 물리값으로 구성된 계약이다. 도착은 `serverNow >= arriveAt`이면 논리적으로 즉시 성립한다. 조회는 도착 위치를 반환하지만 계약이나 함선 revision을 갱신하지 않는다.

수동항해는 로컬에서 자유롭게 표현한다. 서버에는 의미 있는 시작·중단·정지 경계만 보낸다. 정지한 함선은 위치 패킷을 계속 보내지 않는다.

필드 함선 목록은 접속자 목록이 아니다.

- 섹터 진입 시 D1 권위 스냅숏을 한 번 읽는다.
- 같은 섹터의 자동항해 함선은 계약으로 위치를 파생한다.
- Presence DO는 접속 중 pose 보간만 선택적으로 전달한다.
- Presence 연결 시 D1 필드 목록을 중복 조회하지 않는다.
- 안전망 필드 조회 주기는 5분이며 숨겨진 탭에서는 중단한다.
- 다음 단계에서는 섹터 변경 cursor를 추가해 전체 스냅숏을 변경분 조회로 교체한다.

## 5. 도메인별 서버 이전

### 5.1 자산과 저장소

채굴과 거래보다 먼저 함선 화물과 정거장 재고를 WORLD_DB의 정규화 테이블로 이전한다. LEGACY_DB의 `assets_json` 전체 저장은 이전 기간의 임시 호환 경로다.

필요한 권위 테이블:

- 캐릭터 자산 계정과 revision
- storage location
- quantity item
- unique item
- slot assignment
- 도메인 명령 receipt

도킹은 좌표가 아니라 `ship_custodies`의 소속이다. 화물 저장소는 함선 UID를 따르며 도킹과 언도킹으로 복제하지 않는다.

### 5.2 채굴

`START_GATHERING`과 `STOP_GATHERING`만 권위 경계로 사용한다.

1. 명령 시각까지 해당 노드의 모든 활성 채굴자를 결산한다.
2. 노드 잔량과 각 함선 화물을 같은 트랜잭션에서 변경한다.
3. 참여자 변화 이후의 rate와 종료 경계를 다시 고정한다.
4. 조회는 노드 epoch와 현재 시각으로 진행량만 파생한다.

heartbeat는 정확성 근거가 아니다. 수동 중단 명령 자체가 결산 이벤트다.

### 5.3 무역

거래는 도킹한 함선 화물과 해당 건물의 station inventory 사이 단일 원자 이전이다.

- 실행 시점에 재고, 용량, 소속을 hard validation한다.
- 가능한 정수 수량만 clamp하여 이동하고 결과를 즉시 확정한다.
- 하역 시간은 이미 확정된 거래의 점유와 표현이다.
- 상대 플레이어의 온라인 여부를 확인하지 않는다.
- 플레이어 간 거래는 만료 시각을 가진 비동기 제안과 수락 명령으로 확장한다.

### 5.4 전투

전투는 총알·피격 동기화가 아니라 작전 계약이다.

- `START_OPERATION`에서 위치, 대상, 소모 자원과 장비를 검증한다.
- 전력, 규칙 버전, seed, `resolveAt`을 고정한다.
- 종료 이후 첫 조회 또는 후속 명령은 결과를 파생하고, 피해·손실·보상을 한 번 결산한다.
- 클라이언트 전투 장면은 같은 seed와 결과 로그를 재생한다.

## 6. 현재 구현 상태

완료:

- 항해와 Beta Space 진입·귀환의 서버 권위
- 도킹 소속과 건물 좌표 기반 위치 해석
- 항해·Beta Space 만료의 순수 조회
- 베타보이드 세대와 재생성의 서버 결정론적 파생
- 활성 Beta Space 세션을 요구하는 베타보이드 처리 명령
- 자원 노드 수명주기의 서버 `WORLD_RECONCILE`
- Presence 연결 시 중복 D1 필드 조회 제거
- 필드 안전망 조회 5분 전환

이전 중:

- 전체 섹터 스냅숏을 cursor 변경분 조회로 전환
- 플레이어 자산과 정거장 재고를 WORLD_DB 정규화 저장소로 이전

아직 로컬 권위가 남은 영역:

- 채굴 로그와 노드 잔량 변경
- 무역 재고 이전
- fitting과 일부 전체 자산 snapshot 저장
- 실제 전투 작전과 결과 결산
- 생산과 시설 자원 결산

## 7. 구현 순서

1. 순수 조회와 결정론적 월드 수명주기 안정화
2. WORLD_DB 자산·저장소 정규화와 초기 계정 생성
3. 채굴 start/stop/settle 서버 이전
4. 무역 단일 원자 이전 서버 이전
5. 생산 lazy settlement 서버 이전
6. 작전 기반 전투 서버 이전
7. 섹터 cursor, 비동기 채팅과 알림 추가

각 단계가 끝나기 전에는 다음 도메인의 로컬 결과를 서버 권위처럼 취급하지 않는다. 임시 경로는 코드와 이 문서에서 명시하고, 서버 명령으로 교체된 시점에 제거한다.
