# 온라인 권위 월드 최종 결정

작성일: 2026-08-02

이 문서는 온라인 이관 과정에서 확정된 결정을 기록한다. 초안인 `05_CostEfficientAuthoritativeServerPlan.md`와 충돌할 경우 이 문서와 `08_OnlineMigrationContract.md`의 최신 확정 사항을 우선한다.

## 1. 기본 원칙

- 서버는 모든 게임 결과의 최종 권위자다.
- 클라이언트는 서버 상태를 표현하고 명령을 요청하는 뷰어다.
- 실시간 자유조작은 개인의 조작 경험이며 경제적·전투적 판정의 권위가 아니다.
- 월드는 로그인 여부와 무관하게 존재한다. 함선, 자원, 건물과 점유 계약은 로그아웃으로 제거되거나 정지하지 않는다.
- 주기 pull, 위치 heartbeat, 상시 Presence는 기본 게임 경로에 두지 않는다.
- 유의미한 명령 직전에 필요한 상태를 읽고 검증한다. 아무 행동도 하지 않는 클라이언트는 게임 시작 이후 서버 부하를 만들지 않아도 된다.

## 2. 함선 배치 상태

함선 배치는 다음 세 상태 중 하나다.

- `FIELD`: 함선 자체의 권위 좌표가 있다.
- `DOCKED`: 함선 좌표가 없고 `ship_custodies`의 소속만 있다. 화면 좌표는 현재 소속 건물 좌표에서 파생한다.
- `BETA_SPACE`: 공용 시간제 공간의 세션과 내부 좌표가 있다.

`arrived`는 이동 상태이고 `docked`는 소속 상태다. 둘은 독립적이다. `arriveAt`과 `dockAt`도 같은 값이나 같은 의미로 취급하지 않는다.

Beta Space 진입 시 `betaVoidId`, `generation`, 진입 좌표를 세션에 고정한다. Beta Void가 만료·재생성되어 다른 좌표로 이동해도 함선은 진입 당시 좌표로 귀환한다.

## 3. 권위 이동 계약

자동항해와 하이퍼드라이브는 서버가 발급하는 타임스탬프 기반 이동 계약이다.

- `flightAt`: 실제 비행 구간이 시작되는 시각
- `arriveAt`: 물리적으로 도착한 시각
- `settledAt`: 서버가 도착을 DB에 물질화한 시각
- `checkpointAt`: 다음 수동 이동 검증의 기준시각

도착 물질화가 늦어져도 `checkpointAt = arriveAt`이다. `settledAt`이나 조회 시각으로 바꾸지 않는다. GET은 논리적 도착 상태를 파생할 수 있지만 revision을 변경하지 않는다. 다음 권위 명령이 도착을 물질화할 수 있다.

결정론적 명령은 클라이언트에서 즉시 애니메이션을 시작하지 않는다. 서버 응답을 받은 뒤 실행한다. 요청은 짧은 만료시각과 `client_action_id`를 가지며, 실패한 원본 명령을 성공할 때까지 재전송하지 않는다. 응답 유실 여부만 receipt로 확인한다.

## 4. 로컬 수동 자유항해

수동 자유항해는 위치 패킷을 주기적으로 전송하지 않는다. 로컬 상태는 IndexedDB `playerShip`에 1초 간격으로 저장하며 `pagehide`와 탭 비활성화 때 마지막 저장을 시도한다.

저장 레코드는 권위 상태가 아니라 우선 복원 후보다.

```text
projection_type = MANUAL_NAVIGATION
projection_version
ship_id
player_id
base_ship_revision
base_contract_id
base_checkpoint_at
position
rotation
speed
desired_speed
saved_at
```

게임 시작 시 저장 시점부터 현재까지의 수동 비행을 로컬 물리로 파생한 뒤 `MANUAL_RESUME`으로 서버에 제출한다. 다음 조건을 모두 통과해야 새 서버 revision으로 확정된다.

- 같은 플레이어와 함선이다.
- 서버의 ship revision이 `base_ship_revision`과 같다.
- 함선은 `FIELD`이며 점유·이동·Beta Space 계약이 없다.
- 서버 기준점과 경과시간 및 함선 물리값으로 도달 가능한 좌표다.
- 위치가 유효해야 한다. 속도·목표속도·회전은 서버 물리 한계로 clamp한다.

다른 서버 액션으로 revision이 바뀌었으면 로컬 후보는 폐기한다. 로컬 후보가 최종 권위를 덮어쓰는 경우는 없다. 다만 서버가 후보를 승인한 뒤에는 그 좌표가 새로운 권위 기준점이므로 사용자 관점에서는 로컬 자유항해가 우선 복원된 것처럼 동작한다.

로그아웃 중 자유항해는 계속될 수 있다. 시간 cap과 연료 cap은 추후 게임 규칙으로 추가할 수 있지만 자유항해 권위 모델과는 별개다.

## 5. 월드 결정론

- 자원 재생성, Beta Void 재생성, 월드 이벤트 결과는 서버에서 결정론적으로 파생한다.
- 난수는 `WORLD_ENTROPY_SECRET`과 이벤트 컨텍스트의 HMAC-SHA-256에서 파생한다.
- bootstrap, 일반 API, 관리자 API에 내부 seed를 반환하지 않는다.
- 같은 경계시각과 컨텍스트는 같은 결과를 만들지만 클라이언트는 미래 결과를 미리 계산할 수 없다.
- 자원 reconcile은 `next_check`가 지난 경우에만 월드 엔티티를 읽는다.

## 6. 경제와 점유

- 정박, 무역, 채광, 생산, Beta Space, 전투 작전은 서버 명령이다.
- 무역 처리시간은 표현용 대기가 아니라 실제 함선 점유 계약이다.
- 채광은 heartbeat가 아니라 시작·종료 경계와 서버 시각으로 결산한다.
- 플레이어 자산과 건물 재고는 같은 `WORLD_DB` 원자 트랜잭션에서 변경한다.
- 클라이언트의 자산 snapshot 전체 업로드는 제거 대상이다.

## 7. 다른 플레이어 관찰

- 모든 함선은 로그아웃 후에도 월드에 남는다.
- 다른 함선은 마지막 권위 이동 계약을 기반으로 표시한다.
- 고스트처럼 오래되거나 섹터 경계에서 갑자기 사라지는 표현은 허용한다.
- 특정 플레이어 조회는 `characterId` 또는 `shipUid` 기반의 명시적 관찰 요청으로 수행한다.
- 스캐너는 먼저 서버 권위 좌표를 확인하고, 필요할 때만 짧은 제한 세션으로 상대의 수동 자유항해 좌표를 중개한다.
- Beta Space는 `betaVoidId + generation`으로 식별하는 공용 시간제 공간이다. 입장 인원과 내부 실시간 공유 방식은 별도 결정한다.
